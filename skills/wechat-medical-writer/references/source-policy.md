# Source Policy

## 1. Source classes

每条医学事实都应能归入以下来源类型之一：

| source_type | 含义 | 默认可信度 |
|---|---|---|
| `user_source` | 用户上传的 PPT/PDF/论文/说明书/内部资料 | 作为任务主资料，但不等于已外部核验 |
| `external_primary` | 指南、共识、药监/注册资料、原始研究、系统评价等一手来源 | 高 |
| `external_secondary` | 综述、学会解读、教材、专业媒体 | 中 |
| `model_inference` | 模型基于已知资料做出的解释、归纳或推断 | 不能单独支撑高风险医学结论 |

## 2. 默认模式：source-first

- 用户资料决定文章的主题、术语、框架和主要观点。
- 资料中的数字、研究结论、适应证、监管状态仍需进入 Claim Ledger。
- 若资料存在明显宣传性语言，先保留为“来源原表述”，再转为中性医学表达；无法中性化且无证据支持时删除。
- 不把模型记忆中的医学知识悄悄混进“用户资料结论”。

## 3. source-only

用户明确要求“只根据这些资料写”时：

- 只使用当前提供资料。
- 不进行外部搜索。
- 不补充资料未出现的数字、推荐、机制或结论。
- 对缺口明确标注“现有资料未提供”。

## 4. research-update

用户明确要求“查最新指南/论文/核验”时：

1. 先读取用户资料，建立待核验清单。
2. 再检索外部一手来源。
3. 对用户资料与外部新证据分别标注。
4. 若两者冲突，不替用户资料“静默纠错”；在 review notes 中说明差异。
5. 文章采用当前核验后的表述，但保留来源链。

## 5. 私有资料与仓库

原始 PPT、PDF、ZIP、说明书、内部培训资料、未公开研究资料默认不提交 GitHub。

推荐本地目录：

```text
~/medical-content-library/<domain>/
```

仓库中只保存：

- 写作规则
- 证据规则
- 模板
- 高层领域 taxonomy
- 不含敏感原文的结构化知识索引

如果未来需要保存结构化摘要，必须避免复制大段原文，并保留来源文件/页码引用信息。
