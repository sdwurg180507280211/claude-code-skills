# Medical Constraints

本文件只补充通用 Writer 通常不具备的医学事实边界，不规定文章结构或写作方法。

## 1. 资料角色要分清

- 用户上传的医学 ZIP/PPT 可以用于定义长期内容方向，也可以在用户明确要求时作为某篇文章的资料来源。
- 领域资料不自动等于唯一事实来源。
- 用户提供的公众号样稿可以作为结构、语气、信息密度和完成度参考，但样稿中的数字、指南结论和参考文献不能因为“出现在样稿里”就视为已核验。
- 产品课件、内部培训材料和营销材料不能单独证明适应证、优越性、监管状态或绝对化结论。

## 2. 不虚构医学来源

不得虚构或补造：

- 指南 / 共识名称、年份、推荐等级；
- 论文作者、期刊、DOI、样本量、终点、统计量；
- NMPA / FDA / EMA 等监管状态；
- 说明书、注册证、适应证、禁忌证；
- 疗效、安全性、风险、患病率或保护效力数字。

来源不足时，明确说明“当前资料不足以支持该结论”。

## 3. 研究时优先可追溯来源

当用户明确要求“研究、核验、更新、查最新指南/论文”时，优先使用与问题直接相关的原始或权威来源，例如：

- 官方指南 / 专业学会指南与共识；
- 药品说明书、医疗器械注册资料、监管机构资料；
- 原始临床研究、系统评价 / Meta 分析；
- WHO、IARC、国家卫生健康部门等权威机构资料。

具体检索、引用格式、研究笔记和大纲仍由主 Writer 的原生流程决定，本 Skill 不另起一套 research workflow。

## 4. 不把表达优化变成事实改写

如果后续使用 Viral Writer 或其他表达优化 Skill：

- 可以优化标题、开头、节奏、段落和可读性；
- 不得为了“更抓人”把“可能、相关、提示”改成“必然、证实、导致”；
- 不得新增恐惧性医学结论；
- 不得改动医学数字、适用人群、时间范围、统计结论和引用关系；
- 不得自行加入“唯一、首个、最安全、最有效、无痛、无创、治愈”等结论。

## 5. 不强加额外产物

除非用户明确要求，不强制生成：

- Claim Ledger；
- source-map；
- 固定审核表；
- 固定工作目录；
- 固定医生端 / 患者端模板；
- 固定篇幅和章节数量。

文章如何组织，由用户当前要求、参考样稿和主 Writer 的成熟流程共同决定。
