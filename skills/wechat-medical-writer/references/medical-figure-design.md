# 医学公众号 Figure 设计约束

> 用途：约束医学公众号中的统计图、论文式 Figure 与多面板图。它不是图片生成器，也不是医学知识库。
>
> 核心原则：**参考图提供复杂度与视觉语法，当前冻结稿提供内容，已核验来源提供数字。**

## 1. 三种输入必须分开

制作 Figure 前，把输入分成三类：

```text
current_article      当前已冻结/接近冻结的正文或最终 HTML
verified_sources     已核验论文、指南、官方来源及其中可追溯数据
visual_references    用户提供的论文图、公众号截图、Figure 样稿
```

职责不同：

- `current_article` 决定**画什么**；
- `verified_sources` 决定**数字和医学结论能不能画**；
- `visual_references` 只决定**复杂度、面板密度、图例/坐标/Caption 的视觉方式**。

禁止：

- 因为参考图有弦图、年龄分层、季节曲线，就在当前文章没有这些内容/数据时也照画；
- 从参考图复制医学数字、结论或 Reference，当作当前文章的证据；
- 为了让图“复杂”而补造未被正文和来源支持的数据。

一句话：

> **借复杂度，不借内容；借版式，不借证据。**

## 2. 先从当前文章反推 Figure 任务

在生成图片前，先从当前冻结稿/HTML 提取最值得视觉化的信息结构。优先候选：

```text
真实统计结果 / 风险差异
自然史 / 时间路径
风险分层
检查或诊疗路径之间的关系
不同检测回答的问题
研究设计 / 主要终点
证据对比
基因型 / 亚组分布
```

每张 Figure 建立一个最小内容契约：

```text
figure_goal          这张图帮助读者理解什么
source_claims        正文中哪些已核验结论支撑它
source_numbers       允许进入图中的真实数字
panels               A/B/C/D 各面板分别表达什么
must_not_infer       不允许模型自行推演的内容
caption_source       Figure caption 对应正文引用编号/文献
```

如果当前文章只能支持一个简单的比较，就画简单统计图；不要为了追求论文感硬扩成四面板。

## 3. 复杂度分级

### Tier 1：单图统计图

适用：一个主要数据问题。

```text
bar / horizontal bar
line
forest plot
scatter
stacked bar
```

应包含：坐标、单位、真实数值、必要时 95% CI、图例、Figure caption。

### Tier 2：组合 Figure

适用：同一论点有 2 个互补维度。

例如：

```text
A. 基因型个体风险
B. 累积归因 / 临床解释
```

### Tier 3：多面板科学 Figure

适用：当前文章本身包含多个互补信息结构，且每个 Panel 都有来源支持。

常见组合：

```text
A. 自然史 / 流程
B. 定量风险图
C. 风险分层矩阵
D. 检查/诊疗作用矩阵
```

或：

```text
A. 主要基因型分布
B. 分组贡献
C. 亚组/时间趋势
D. 临床解释
```

复杂度来自**信息维度与互补关系**，不是来自装饰元素数量。

## 4. 论文式视觉语法

用户提供论文 Figure 作为参考时，可借鉴：

```text
A / B / C / D 面板编号
白底
黑/深灰坐标与文字
克制的医学配色
细灰分隔线
清晰图例
真实数值标签
95% CI / n（来源支持时）
英文 Figure caption
中文图注
正文引用编号
```

不要把论文 Figure 改成卡通科普信息图；也不要为了“品牌感”给数据图加过多丝带、人物、3D、光效或装饰图标。

## 5. 数据完整性

硬约束：

- 图中所有医学数字必须能回到 `verified_sources`；
- 图像生成模型不得自行补数字、CI、样本量、时间范围或研究结论；
- 若来源只支持摘要层面的数字，不要虚构更细的年龄组/月份/亚组；
- 概念流程图没有可靠数字时可以不写数字；
- 不把人群风险直接写成某个个体的预测值；
- 不把相关性画成确定因果；
- 同一 Figure 中若混合多个研究来源，Caption 必须说清楚，不伪装成单一研究图。

如果生成模型把 DOI、PMID、期刊名、作者写错，**不要把错误来源留在图片里**。优先让图片只承载图形和必要标签，正式来源由 HTML 图注和 References 管理。

## 6. Figure 与正文的连接

成熟医学公众号不要把图孤立地插进去。优先结构：

```text
正文先提出结论 / 数据
↓
Figure
↓
English Figure caption（可选，跟随样稿）
↓
中文图注 + 正文引用编号
↓
继续正文，只解释最重要 takeaway
```

图前正文回答“为什么现在看这张图”；图后不要把图里每个数再复述一遍。

对于“光愈在线式”文章，若参考样稿采用：

```text
正文引入句
→ 灰色分隔线
→ 图
→ English Figure caption
→ 灰色分隔线
→ 中文图注
```

可以复用这一**视觉语法**，但 Caption 内容必须来自当前文章和真实来源。

## 7. Reference 闭环

新增 Figure 时同步检查：

```text
[ ] 图前正文是否有对应 [n]
[ ] Figure caption 是否指向同一来源
[ ] References 是否包含该文献
[ ] 删除 Figure 后，是否还需要保留仅服务于该图的文献
[ ] DOI / PMID / 年份 / 期刊是否核验
```

不要为了“显得学术”保留正文完全没有使用的参考文献。

## 8. 生成前 QA

```text
[ ] 当前 Figure 的内容是否能从当前冻结稿直接解释？
[ ] 是否只是借鉴参考图的复杂度，而没有照搬参考图内容？
[ ] 每个 Panel 是否都有存在的理由？
[ ] 每个数字是否有来源？
[ ] 有没有为了复杂度发明年龄、月份、亚组或机制？
[ ] 图内是否避免写未经核验的 PMID/DOI/作者？
[ ] 图与正文的引用编号是否闭环？
[ ] 图注是否明显小于正文，且适合手机端阅读？
```

## 9. 与 image generation / plotting 的关系

本文件不规定使用哪一种绘图工具。

- 精确数据图优先用可控绘图工具生成数据锚点；
- 需要更高视觉完成度时，可以基于数据锚点做视觉重绘；
- 如果使用图像生成模型，必须把允许出现的数据与标签明确写入输入，并在交付后复核；
- 生成模型适合提高版式和论文感，**不适合充当医学数据源**。

最终标准不是“看起来像论文”，而是：

> **内容来自当前文章，数字来自真实来源，复杂度服务于理解。**
