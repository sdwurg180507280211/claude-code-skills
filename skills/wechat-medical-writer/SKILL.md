# Medical WeChat Writer

## 目标

把一个医学主题和一组可信资料转成可审阅、可追溯、适合微信公众号/服务号的文章草稿。

本 Skill 只负责医学内容创作与证据整理，不负责公众号排版或发布。需要排版/发布时，可把生成的 Markdown 交给 `canghe-markdown-to-html`、`canghe-article-illustrator`、`canghe-post-to-wechat` 等上游工具。

## 核心原则

1. **资料优先**：用户提供的课件、论文、指南、说明书优先于模型常识。
2. **不静默补全**：资料没有支持的医学事实，不自行补成确定性结论。
3. **来源分层**：区分用户资料、外部一手来源、外部二手来源、模型推断。
4. **关键结论可追溯**：疗效、安全性、适应证、指南推荐、数字、比较优势、监管状态等进入 Claim Ledger。
5. **写作与核验分开**：先形成文章，再对关键医学表述做证据和合规复核。
6. **受众适配**：医生端和患者端必须使用不同结构与语言，不能把医生课件直接降级改写成患者科普。
7. **原始资料不入库**：PPT/PDF/ZIP/说明书等原件默认保存在用户本地或私有资料库，不提交本 GitHub 仓库。

## 三种资料模式

### `source-only`

只允许使用用户提供资料。资料不足时明确写“现有资料不足以支持该结论”，不得用常识补齐。

### `source-first`（默认）

以用户资料为主。需要解释性背景时可以使用稳定医学常识，但新增事实必须标记为外部知识或待核验，不得与用户资料混写成同一来源。

### `research-update`

用户明确要求“查最新指南/论文/核验/更新”时使用。优先检索指南、共识、注册/说明书、原始研究等一手来源，并与用户资料分开标注。

详细规则见 `references/source-policy.md` 与 `references/evidence-policy.md`。

## 工作流

```text
主题 / 任务
↓
确认受众与文章类型
↓
读取用户资料
↓
建立 Source Map
↓
提炼临床问题 / 核心观点
↓
生成大纲
↓
建立 Claim Ledger
↓
撰写初稿
↓
医学事实复核
↓
合规与表述风险复核
↓
输出 Markdown + Claim Ledger + 待核验项
```

## 文章类型

### 1. 医生端学术文章
适合临床问题、诊疗策略、风险分层、治疗选择。

推荐结构：

```text
临床问题
→ 当前难点
→ 指南/共识
→ 关键证据
→ 风险分层
→ 临床决策
→ 实践要点
```

模板：`templates/hcp-academic.md`

### 2. 指南 / 共识解读

```text
为什么更新
→ 关键推荐
→ 与既往相比的变化
→ 哪些患者受影响
→ 对临床实践意味着什么
→ 注意事项
```

### 3. 患者科普

```text
患者最关心的问题
→ 概念解释
→ 为什么会这样
→ 哪些情况需要观察/治疗
→ 治疗选择如何讨论
→ 就医时应问医生什么
```

模板：`templates/patient-education.md`

### 4. 临床证据文章

```text
PICO / 临床问题
→ 研究设计
→ 入组人群
→ 主要终点
→ 关键结果
→ 安全性
→ 局限性
→ 临床意义
```

### 5. 产品医学教育

必须额外核对：

```text
说明书 / 注册资料
→ 允许表述范围
→ 证据来源
→ 医学教育内容
→ 合规检查
```

不得仅根据营销课件自由扩展产品疗效、适应证、唯一性、优越性或监管结论。

## Claim Ledger

每篇正式文章都要为关键医学结论建立 Claim Ledger。最少字段：

```text
claim_id
claim_text
claim_type
source_type
source_ref
source_location
evidence_level
verification_status
public_use_status
notes
```

高风险 Claim 包括：

- 适应证 / 禁忌证 / 用法用量
- 疗效百分比、OR、HR、RR、P 值等数字
- 不良反应、安全性结论
- “优于 / 更安全 / 更有效 / 无痛 / 无创 / 唯一 / 首个”等比较或绝对化表述
- 指南/共识推荐
- NMPA/FDA/EMA 等监管状态
- 生育结局、进展风险、复发风险
- 产品或治疗流程中的具体操作参数

使用 `scripts/validate_claim_ledger.py` 做结构校验。

## 输出契约

默认输出：

```text
article.md
claim-ledger.json
source-map.md
review-notes.md
```

`article.md`：可读文章草稿。

`claim-ledger.json`：关键医学结论的证据追溯表。

`source-map.md`：本次实际使用了哪些资料，以及哪些是外部新增来源。

`review-notes.md`：待医学审核、待合规审核、资料不足或存在冲突的点。

## 禁止事项

- 不把用户上传的原始医学资料直接提交到仓库。
- 不因为课件中出现某个数字，就自动视为已核验事实。
- 不把产品推广性语言直接改写成医学结论。
- 不虚构指南、论文、作者、年份、样本量或统计结果。
- 不把“可能、提示、相关”改写成“证实、必然、治愈”。
- 不在资料不足时擅自给出患者个体诊断或治疗建议。

## 运行时资料

推荐把私有资料放在仓库外，例如：

```text
~/medical-content-library/
└── cervical-health/
    ├── slides/
    ├── papers/
    ├── guidelines/
    ├── labels/
    └── notes/
```

如果用户在当前会话直接上传 ZIP/PPT/PDF，则读取当前附件即可，不需要复制到仓库。
