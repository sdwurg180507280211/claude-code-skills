# AI Model WeChat Writer

## 定位

这是一个面向 **AI 大模型 / API 价格 / 免费额度 / 高性价比使用渠道** 的微信公众号编辑与编排层。

它不重新实现通用研究写作，而是负责把原始“情报”加工成可发布的公众号选题：

```text
原始情报
→ 判断文章类型
→ 提炼读者决策问题
→ 规范价格 / 渠道 / 风险字段
→ handoff 给 content-research-writer
→ 数据表 / 信息卡 / 科技媒体排版
→ 微信 HTML / 人工复核 / 发布
```

通用研究、论证、正文写作和引用组织必须优先交给：

```text
content-research-writer
```

本 Skill 只增加 AI 模型“省钱情报”特有的编辑判断、价格比较、渠道风险与排版规范。

## 典型输入

优先输入之一是定时任务 **“AI模型省钱情报”** 的每日结果，也可以是：

- 模型厂商官方发布公告；
- 官方 API 定价页、免费额度说明、开发者文档；
- 云平台 / 正规聚合平台的模型接入与优惠信息；
- 用户提供的模型列表、价格表或历史日报；
- 权威媒体对模型发布和价格变化的报道。

原始情报是“编辑素材”，不是可以原封不动发布的正文。

## 文章类型路由

在开始写正文前，先判断文章应该属于哪一类。

### 1. AI 模型省钱日报

适合：过去 24 小时有多条会影响模型选择、价格或使用渠道的变化，但没有一条足以独立成为重大专题。

目标：**30 秒告诉读者今天该用谁、为什么、在哪里最划算。**

建议篇幅：1500～2500 中文字。

模板见：

```text
templates/daily.md
```

### 2. 重大更新 / 单篇深度

出现以下情况时，不要硬塞进日报：

- 头部厂商发布新的旗舰或关键模型；
- API 价格显著变化；
- 免费额度、上下文、限速、地区或接入方式发生重大变化；
- 一个事件足以改变“编程 / 推理 / 长文本 / 图像 / Agent”等场景的模型选择。

目标：围绕一个核心问题讲透“强不强、适合谁、贵不贵、怎么用最划算”。

### 3. 周报 / 性价比榜

适合把最近 7 天已核验信息重新聚合，按使用场景给出：

- 编程最值；
- 推理最值；
- 日常问答最值；
- 长文本最值；
- 免费使用最值；
- API 批量调用最值。

周报不是把 7 篇日报拼起来，必须去重并只保留仍然有效的信息。

## 公众号编辑原则

### 先回答“怎么选”，再讲新闻

文章开头避免“随着 AI 快速发展”一类背景铺垫。

优先顺序：

```text
今天发生了什么
→ 这会不会改变模型选择
→ 哪个模型现在更划算
→ 适合什么任务
→ 去哪里用
→ 有什么坑
```

### 不按新闻条数凑数

如果当天只有 3 条高价值变化，就只写 3 条。

不要为了维持“中国 5 条 + 国外 2 条”的采集结构，把低价值新闻全部搬进公众号。

### 每篇必须有明确决策结论

至少给出一个可快速扫描的“今日最省钱结论”区域，推荐 1～3 个模型或渠道，并说明适用场景。

## 价格与渠道事实约束

详细输入契约见：

```text
references/intelligence-contract.md
```

核心规则：

1. **价格优先官方来源。** 官方定价页、官方文档、云平台官方页优先于媒体和社区转述。
2. 必须记录核验日期；涉及限时活动时记录结束时间或明确“结束时间未核实”。
3. API 价格尽量统一到“每 1M tokens 输入 / 输出”，同时保留原币种；如果做人民币换算，标明只是按当日汇率近似换算。
4. 不把缓存命中价、Batch 价、Prompt Caching、套餐摊销价与标准按量价混为一谈。
5. 不把“免费体验”“新用户额度”“永久免费层”写成同一概念。
6. 上下文窗口、速率限制、每日额度、并发限制会影响性价比时必须写出。
7. 价格无法核实时明确写“当前未核实”，不得补造数字。
8. 同一模型可能存在官方、云平台、聚合平台和中转站多个入口，必须区分渠道类型。

## 渠道风险标签

建议使用统一标签：

```text
[官方]
[云平台官方接入]
[正规聚合平台]
[非官方中转]
```

非官方中转站不得仅用“便宜”作为推荐理由。至少提醒：

- 数据隐私；
- API Key / 账户安全；
- 稳定性和限流；
- 模型版本真实性；
- 服务中断 / 跑路；
- 封号或违反原厂服务条款的风险。

禁止推荐盗号、共享密钥、来源不明 API Key、绕过地区限制或明显违反服务条款的渠道。

## Handoff 给主 Writer

在正文写作之前，把已经整理好的编辑 Brief 交给 `content-research-writer`，至少包含可获得的：

```text
topic              今日主线 / 单篇核心事件
audience           AI 使用者 / 开发者 / 小团队 / 企业等
article_type       daily / breaking / weekly
goal               帮读者做模型与成本决策
source_window      情报覆盖时间范围
top_picks          1～3 个优先推荐模型/渠道
price_facts        已核验价格、币种、计价单位、核验日期
channel_facts      官方/云平台/聚合/中转分类与限制
model_strengths    编程/推理/长文本/图像/Agent/搜索等
risk_notes         数据、稳定性、条款与渠道风险
primary_sources    官方公告/定价页/文档
layout_profile     references/layouts/ai-savings-daily.md
```

已经知道的信息不要重复询问用户。

如果运行环境缺少 `content-research-writer`，应明确提示安装同仓库该 Skill，不得悄悄复制一套 fallback Writer。

## 标题原则

日报标题强调“今天发生了什么 + 对选择有什么影响”，避免纯列表标题。

优先类型：

```text
Claude突然降价，DeepSeek还值得用吗？今天最省钱的3个AI模型
GPT新模型价格变了：写代码现在用谁最划算？
今天别急着续费：3个AI模型的价格/免费额度刚变
```

不应：

```text
AI行业最新资讯汇总
今日人工智能新闻7则
全球大模型发展趋势分析
```

标题里的“最便宜 / 最强 / 第一”必须能由当前比较范围支持；范围不完整时改成“更划算 / 值得关注 / 当前推荐”。

## 数据视觉与排版

默认读取：

```text
references/layouts/ai-savings-daily.md
```

视觉目标是 **科技情报刊 / 数据决策卡**，而不是 AI 插画海报。

优先级：

```text
数据表 / 信息卡 / 排名
> 简单数据图
> 产品官方视觉
> 装饰性 AI 插图
```

一般一篇日报 2～4 个视觉组件即可：

- 今日最省钱结论卡；
- TOP 模型信息卡；
- 价格 / 能力对比表；
- 必要时一个价格柱状图或场景雷达图。

没有足够数据时不要为了“有图”生成伪数据图。

## 发布前检查

发布前至少确认：

- 标题与正文中的模型版本一致；
- 价格的输入 / 输出、币种、计价单位一致；
- 免费额度没有把一次性额度写成永久免费；
- 活动价格没有被写成长期标准价；
- 官方与第三方渠道标识正确；
- 关键价格和重大更新可以回到实际来源；
- 表格里没有旧版本价格；
- “今日推荐”是真正基于当日信息，而不是固定品牌偏好；
- 文章结尾有信息来源与风险提示；
- 微信 HTML 在手机窄屏上表格仍可读。

默认做到“可直接发布但仍需人工复核”的 HTML / 富文本，不自动替用户发布，除非用户明确要求并且当前环境已有可用的发布工具。
