# AI 模型省钱日报｜视觉与排版画像

适用：`wechat-ai-model-writer` 的 `daily` 栏目，以及风格相近的周报。重大更新文章可以继承 Token，但不要求套完整日报组件。

## 视觉定位

关键词：

```text
科技情报刊
数据决策卡
干净
可信
克制
高信息密度
手机优先
```

避免：

- 大量渐变、发光、赛博霓虹；
- 每一段都做成卡片；
- 用 AI 插画替代真实数据；
- 五颜六色的品牌 Logo 墙；
- 过度模仿某个模型厂商自己的品牌视觉。

## 基础 Token

建议默认值：

```text
页面背景        #FFFFFF
正文文字        #222222
次级文字        #667085
弱提示          #98A2B3
主强调色        #2563EB
主强调浅底      #EFF6FF
中性卡片底      #F7F8FA
边框            #E5E7EB
风险文字        #B42318
风险浅底        #FEF3F2
正向/降价文字   #067647
正向浅底        #ECFDF3
```

原则：全篇主要使用“蓝 + 黑灰”，绿色只用于明确的降价 / 省钱信息，红色只用于风险或价格上涨，不把颜色当装饰。

## 正文排版

推荐：

```text
正文                15.5～16px
正文行高            1.75～1.85
段落间距            14～18px
一级章节标题        21～23px / 700
模型小标题          18～20px / 700
辅助标签            11～12px
表格正文            12～13px
来源 / 注释          11～12px
```

手机端优先控制单段为 2～4 行；复杂信息宁可拆段，也不要形成大段文字墙。

## 页面节奏

推荐顺序：

```text
标题
短导语
↓
今日最省钱结论卡
↓
正文 01
↓
模型信息卡 / 小表
↓
正文 02
↓
核心价格对比表
↓
正文 03
↓
今天怎么选
↓
风险提示
↓
来源
```

不要把结论卡、模型卡、表格连续堆在一起，中间至少穿插解释性正文，让读者知道“为什么”。

## 组件 1：今日最省钱结论卡

用途：文章首屏核心资产。

内容最多 3 个推荐：

```text
今日最省钱

编程：Claude XXX
原因：XXXX

API 批量调用：DeepSeek XXX
原因：XXXX

免费使用：Qwen XXX
原因：XXXX
```

样式：

- `background: #EFF6FF`
- `border-left: 4px solid #2563EB`
- `border-radius: 10px`
- 内边距约 `18px 16px`
- 卡片标题 14px / 700 / 蓝色
- 推荐项 15～16px

避免放超过 3 个模型，否则会把“结论”变成列表。

## 组件 2：模型信息卡

每个重点模型可以使用一张卡，但不是所有新闻都要卡片化。

字段建议：

```text
模型名
一句话定位
推荐指数（可选）

适合：编程 / 推理 / 长文本
价格：输入 / 输出
免费：额度或“无已核实免费 API”
渠道：[官方] / [云平台官方接入] / ...
一句话建议：XXXX
```

推荐使用中性浅灰底，不使用厂商品牌色大面积铺底。

## 组件 3：核心价格对比表

这是省钱类公众号最重要的视觉资产之一。

### 优先列

手机端一张表尽量控制 4～5 列：

```text
模型 | 输入价 | 输出价 | 最适合 | 推荐渠道
```

如果还要展示上下文、免费额度、限速，拆成第二张表或移到模型卡，不要强塞 8～10 列。

### 表格规范

- 表头：12px / 700 / `#475467` / 浅灰底；
- 内容：12～13px；
- 数字价格尽量右对齐；
- “更便宜”可以使用绿色文字，但不要整格填绿；
- 表格下方必须有 11～12px 注释，说明币种、单位、核验日期；
- 如果价格模式不同（标准价 / Batch / 缓存），必须在列名或脚注中解释。

### 窄屏规则

微信手机端优先：

1. 减少列数；
2. 模型名允许换行；
3. 价格单位缩写，但脚注完整解释；
4. 复杂表拆成两张；
5. 不依赖必须横向滚动才能理解的超宽表。

## 组件 4：价格变化提示

降价：

```text
↓ 价格变化
输出价格从 X 降到 Y，降幅约 Z%。
```

上涨：

```text
↑ 成本提醒
XXXX
```

只有来源中的旧价和新价都可核实时才计算百分比；否则只写已核实的新价格。

## 组件 5：风险提示

样式：

- `background: #FEF3F2`
- `border: 1px solid #FECDCA`
- `border-radius: 10px`
- 标题 `#B42318`

内容示例：

```text
省钱提醒
非官方中转站的低价不等于低风险。企业代码、客户数据、医疗/金融等敏感内容不要上传到来源不明的渠道；共享 Key 还可能存在封号和泄露风险。
```

风险卡一篇通常只需要一张。

## 组件 6：来源区

标题建议：

```text
信息来源与价格核验
```

来源按优先级排序：官方公告、官方定价、官方文档、云平台官方页、权威媒体。

每条来源尽量包含：

```text
来源主体｜页面/公告名称｜核验日期
```

正文已经有超链接时，来源区可以简化，但不要把来源完全隐藏。

## 标题与章节样式

一级章节推荐：

```text
01
DeepSeek：批量推理仍然更划算吗？
```

视觉上可把 `01` 作为小号蓝色编号，把真实标题作为黑色粗体。

不要使用大量“第一部分 / 第二部分 / 第三部分”的论文式标题。

## 图表

优先使用数据图，而不是装饰插图。

适合：

- 同类计费模式下的输入 / 输出价格柱状图；
- 明确来源数据的模型场景矩阵；
- 一周价格变化趋势。

慎用雷达图：只有评分标准、评分来源和比较范围明确时才使用。不要由模型主观打 1～5 分然后画成“性能雷达图”。

## 封面方向

日报封面应形成固定栏目识别：

```text
AI省钱情报
DAILY

主事件 1
主事件 2

今天最值得用谁？
```

更像财经 / 科技媒体封面，不使用“机器人头 + 电路线 + 发光脑”等通用 AI 素材。

## HTML 输出要求

- 优先 inline style，以适应微信编辑器对 CSS 的限制；
- 不依赖 JavaScript；
- 不依赖外部字体；
- 重要内容不能只通过颜色区分；
- 正文最大宽度由微信编辑器控制，不硬编码桌面端大宽度；
- 发布前在真实手机宽度检查表格、长模型名、长价格单位和英文 URL 的换行。

基础 HTML 组件骨架见：

```text
templates/daily.html
```
